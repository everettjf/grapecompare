# GrapeCompare 1.6–1.8 — Merge and Integration Contract

## 1.6: three-way merge and tools

- The merge engine takes immutable base, ours, and theirs snapshots. Independent and identical edits resolve automatically; overlapping edits remain first-class conflicts.
- The merge screen requires an explicit base/ours/theirs/both choice for every conflict and keeps the result editable.
- `grapecompare diff` returns 0 for identical files and 1 for differences. The generated difftool wrapper accepts both statuses because a visual difference is not a tool failure.
- `grapecompare merge` returns 0 only for an automatic merge, 1 when conflict markers were written, and 2 for invalid input or an execution failure.
- The generated Git mergetool command launches a new GrapeCompare instance with `--merge`, waits for it, and checks an atomic completion sentinel. The app writes the sentinel only after every conflict is resolved and the merged file is saved.

The GUI mergetool requires a directly distributed build that can access Git's temporary paths. The App Store sandbox does not make arbitrary command-line paths equivalent to files explicitly selected by the user.

## 1.7: repository and Finder integration

- Repository comparison reads branches/tags and supports revision→revision, revision→index, revision→working-tree, and index→working-tree comparisons.
- It includes untracked files when the right target is the working tree and materializes commit/index blobs without checkout, reset, fetch, commit, or other repository mutation.
- The Compare Files App Intent exposes one file collection constrained to exactly two `FileEntity` values. Its generated App Intent metadata is verified after building, so the same action can receive a two-file Finder selection through Shortcuts.

## 1.8: images and structured values

- Image comparison decodes through ImageIO, reports dimensions and pixel metrics, and supports side-by-side, overlay, and red-alpha heatmap views.
- JSON and plist comparison share one semantic tree, ignore object-key order and serialization format, and report stable paths plus added/removed/changed/type-changed states.
- Unsupported or undecodable specialized content falls back to the existing file comparison behavior instead of changing the source data.

## Automated verification

```bash
bash macos/Tests/run-tests.sh
bash macos/CLI/run-tests.sh
ruby macos/Tests/validate-localizations.rb <Xcode Objects-normal/arm64 directory>
ruby macos/Tests/validate-app-intent.rb <built GrapeCompare.app>
```

The core suite covers deterministic fixtures, randomized reconstruction, merge conflicts, external mergetool handoff, all Git state pairs, image pixels, JSON/plist semantics, and the existing safe filesystem operations. CLI integration verifies system `git apply`, BSD `patch`, real `git difftool` invocation, exit statuses, and configuration output.
