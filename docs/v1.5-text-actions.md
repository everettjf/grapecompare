# GrapeCompare 1.5 — Text Actions

## 状态

已实现。本文保留 1.5 的产品规则、实现阶段和验收门槛；1.6–1.8 的后续范围也已在 1.8.0 工作树中实现。

## 版本结论

1.5 聚焦“文件内部的安全操作”：在现有并排文本比较上增加搜索、跳转、比较规则、按差异块选择内容、可编辑输出、统一 diff 导出、语法高亮和自动换行。

以下能力不并入 1.5 GA，但 1.5 的核心模型必须为它们留出稳定接口：

- 三方比较、冲突合并和 Git mergetool：1.6。
- 独立 CLI、Git difftool，以及分支、提交、工作区比较：1.6–1.7。
- Finder Quick Action：1.7。
- 图片和结构化数据比较：1.8，作为独立 comparator，而不是文本 diff 的特殊分支。

原因不是功能价值不足，而是这些能力分别引入三方合并语义、进程/退出码协议、Git 对象读取与沙盒分发、扩展进程权限、非文本渲染模型。将它们与可编辑文本输出一次性交付，会让保存安全性、patch 正确性和回归面无法在一个版本中充分验证。

## Outcome

用户可以在文件内部完成与 1.3/1.4 文件操作一致的工作流：先比较和定位，再明确选择内容，在独立输出中检查或编辑，最后以可审阅、原子且可撤销的方式保存，或导出标准 unified diff/patch。比较选项只改变“如何判断和呈现差异”，永远不悄悄改写原文件。

## 1.5 GA 范围

### 必须交付

1. 文本搜索和行跳转。
2. 比较时可忽略空白变化、大小写和行尾格式。
3. 以差异块为单位接受左侧或右侧内容。
4. 独立、可编辑的输出缓冲区，以及标准 Undo/Redo。
5. 安全保存和另存为；保存前检测磁盘内容是否已变化。
6. 导出全部或所选差异块为 unified diff/patch。
7. 语法高亮和自动换行开关。
8. 英文与简体中文本地化、核心测试、UI 冒烟测试和性能基准。

### 明确不做

- 不直接编辑左右输入；左右两侧始终是本次会话的只读快照。
- 不在 1.5 应用 patch，也不实现目录级 patch。
- 不自动解决冲突，不做实时双向同步。
- 不把“忽略的差异”从保存内容或导出 patch 中删除。
- 不承诺任意文本编码的可编辑性；不能无损解码和回写的文件保持只读。
- 不在文本行模型里加入图片、JSON 树或表格的条件分支。

## Product rules

### 1. 原始内容与比较视图分离

每个输入建立不可变的 `TextSnapshot`，至少保留原始数据指纹、编码、BOM、逐行内容、逐行行尾和是否有最终换行。比较规则生成单独的匹配键；diff 对齐使用匹配键，展示、接受、保存和 patch 始终使用原始内容。

因此必须区分三种状态：

- 字节完全相同。
- 按当前规则等价，但原始内容不同。
- 按当前规则仍有可见差异。

“按规则等价”不能显示成“文件完全相同”，界面应明确说明哪些差异被隐藏，并提供一键恢复精确比较。

### 2. 比较规则有精确定义

- **空白：** `精确`、`忽略空白数量变化`、`忽略全部空白`。数量变化模式把连续水平空白视为一个空格，并忽略行首/行尾水平空白；全部空白模式从匹配键中移除所有水平空白。换行不属于该选项。
- **大小写：** 使用与 locale 无关的 Unicode case folding，仅影响匹配键。
- **行尾：** `精确`或`忽略格式`。忽略格式时 LF、CRLF 和 CR 等价；“是否存在最终换行”仍单独报告，除非用户也明确选择忽略最终换行。

选项变化会取消旧计算并重新生成 diff，沿用当前的 generation/cancellation 机制。选项属于窗口会话，可记住默认值，但不写入文件。

### 3. 搜索与差异导航互不混淆

- `⌘F` 打开当前比较会话的搜索栏；默认搜索两侧，允许限制左侧、右侧或输出。
- 支持普通文本、区分大小写和整词匹配；正则表达式延期，避免首版把性能和错误语义绑定到搜索主流程。
- `Return`/`⇧Return` 前后跳转匹配，结果计数按侧显示。
- `⌘L` 跳转行，接受 `42`、`L42`、`R42` 和 `O42`；缺省跳到当前焦点侧。
- 搜索命中和当前差异使用不同高亮，不改变 diff 统计。

### 4. 差异块是一等模型

现有 `DiffRow` 只够展示，不足以安全接受内容或导出 patch。1.5 增加 `DiffHunk`：稳定 ID、左右原始行范围、上下文范围、精确内容和源快照指纹。行仍是渲染模型，由 hunk 派生。

任何接受动作都要验证 hunk 仍属于当前两个快照。比较规则变化、换边或输入重新载入后，旧 hunk ID 立即失效，不能套用到新结果。

### 5. 输出是第三份文档

- 首次进入编辑模式时，输出默认以右侧快照为基线；用户可以改为以左侧重新开始，但已有手工编辑时必须确认。
- “接受左侧”用该 hunk 的左侧原始行替换输出对应区间；“接受右侧”同理，也可撤回之前接受的左侧内容。
- 每个 hunk 显示 `右侧基线`、`已选左侧`、`已选右侧`或`手工编辑`状态。
- 左右快照不随输出编辑重新 diff；这能保证 hunk 身份、导航和 patch 来源稳定。用户可显式执行“将输出作为一侧重新比较”开始新会话。
- 普通编辑、接受 hunk 和重置输出都进入同一个 `UndoManager`。

输出实现应使用适合编辑的 AppKit 文本组件，而不是让每个 SwiftUI diff 行变成独立编辑器。大文件编辑可以采用分段存储，但不能在每次接受 hunk 后对全文重新 diff。

### 6. 保存沿用安全操作原则

- 默认保存目标为输出基线对应的文件；始终提供“另存为”。
- 保存前比较当前磁盘快照与会话开始时的指纹。目标已变化时停止，并让用户选择重新比较或另存为；不能直接覆盖。
- 在目标同目录写入临时文件，刷新并原子替换；覆盖前保留可撤销备份，并复用 1.4 的持久操作日志和最新事务栈语义。
- 未修改的行保留原行尾；新行使用目标文档的主导行尾。编码和 BOM 默认随目标保留。
- 首版可编辑编码为无损 UTF-8（含可选 BOM）和带 BOM 的 UTF-16 LE/BE。解码存在替换字符风险、编码不明确或回写不可逆时，只允许查看和 patch 原始可表达内容，不允许覆盖保存。
- 关闭窗口、返回主页或重新比较时，如输出有未保存修改，必须提示保存、放弃或取消。

### 7. Patch 始终描述精确内容

- 导出 UTF-8、LF 行尾的 unified diff，包含 `---`、`+++`、`@@`，默认 3 行上下文，并正确输出 `\ No newline at end of file`。
- 可导出全部 hunk 或当前选择的 hunk；路径来自显示名或用户给定的相对标签，不泄露绝对路径。
- patch 从左右原始快照生成，不从归一化匹配键生成。若比较选项隐藏了原始差异，导出前提示切换到精确比较；不得生成无法重建右侧内容的“近似 patch”。
- 二进制文件、无法用文本 patch 无损表达的输入和空的 hunk 选择应明确拒绝。
- 1.5 只负责导出，不负责执行 patch。

### 8. 高亮和换行是渲染策略

- 语言由扩展名和轻量内容探测决定，始终允许切回纯文本。
- 高亮只生成可见范围的属性，不能改变字符、行号、选择范围或 diff 结果；超大文件自动降级并解释原因。
- 自动换行关闭时保留当前同步水平滚动；开启时取消水平滚动，并让同一 diff row 的左右高度取两侧较大值，保持对齐。
- 搜索、行内差异和语法高亮的属性分层合成，优先级为：当前搜索命中 > 行内差异 > 语法颜色。
- 1.5 首发语法集合以项目常见文本为限：Swift、Objective-C/C/C++、JavaScript/TypeScript、Python、Shell、JSON、YAML、Markdown；其他格式回退纯文本。

## Core design

```text
raw Data
  └─ TextDecoder -> TextSnapshot (content + encoding + exact line endings + fingerprint)
       ├─ ComparisonNormalizer(options) -> [LineKey]
       ├─ HunkDiffEngine -> [DiffHunk] -> [DiffRow] -> read-only UI
       ├─ TextOutputSession -> accept/manual edit -> safe save transaction
       └─ UnifiedDiffWriter -> .diff/.patch
```

建议把平台无关能力拆入 `Core/Text`，并保持 Foundation-only：

- `TextSnapshot.swift`：无损解码、行尾、编码和指纹。
- `TextComparisonOptions.swift`：可序列化、可测试的规则。
- `TextDiffEngine.swift`：基于现有 Myers/anchor 算法输出 hunk，再派生 rows。
- `TextOutputSession.swift`：输出基线、hunk 映射、决策状态和编辑版本。
- `UnifiedDiffWriter.swift`：标准 patch 生成。
- `TextWriteOperation.swift`：预检、原子提交、日志与撤销桥接。

UI 层建议把当前 `FileDiffView` 拆成会话容器、工具栏、只读 diff surface、搜索控制器和输出编辑器。语法高亮通过协议注入；后续图片或结构化 comparator 使用另一套 surface，不共享文本 hunk 类型。

为后续 CLI 预留的边界是纯数据输入、纯结果输出和明确错误码映射；1.5 不要求把 App 生命周期、SwiftUI 状态或安全作用域 URL 引入 Core。

## Implementation phases

### Phase A — 精确文本快照与 hunk 重构

- 引入保留编码、BOM 和逐行行尾的 `TextSnapshot`。
- 把现有 `DiffEngine` 的算法核与展示结果分开，产出带原始范围的 hunk。
- 保持当前精确比较、二进制检测、256 MB 物化上限、取消和随机最短编辑脚本测试全部通过。
- 增加 hunk 可重建性属性测试：依次应用所有右侧 hunk 必须精确得到右侧快照。

### Phase B — 搜索、跳转和比较规则

- 实现搜索索引、焦点侧与 `⌘F`/`⌘L` 命令。
- 实现空白、大小写、行尾和最终换行规则。
- 展示“字节相同 / 按规则等价 / 有差异”三态，以及隐藏差异说明。
- 为选项组合、Unicode、空行、混合行尾和最终换行补充矩阵测试。

### Phase C — 接受 hunk 与可编辑输出

- 增加输出面板、基线选择、hunk 决策和统一 Undo/Redo。
- 解决连续插入、删除、相邻 hunk、文件首尾和手工编辑穿过 hunk 边界的映射。
- 增加未保存修改保护和“输出作为一侧重新比较”。
- 对 10 万行文档验证接受单个 hunk 不触发全文 re-diff。

### Phase D — 安全保存与 unified diff

- 实现写入预检、磁盘变更检测、同目录暂存、原子替换和持久撤销。
- 保存时保留编码、BOM、未改行行尾和最终换行。
- 实现全量/选中 hunk patch 导出、路径标签和无最终换行标记。
- 用固定 fixtures 验证 patch 可重建目标，并用系统 `patch` 或 `git apply --check` 做兼容性测试。

### Phase E — 高亮、自动换行与发布收尾

- 完成可见范围高亮、纯文本回退、语言选择和超大文件降级。
- 完成自动换行下的左右行高同步、键盘选择、VoiceOver 标签和深浅色检查。
- 增加 UI 冒烟测试、性能基准、本地化、README、截图和 changelog。
- Debug、unsigned Release、App Sandbox 构建和现有 1.0–1.4 测试全部通过。

## Acceptance gates

- 搜索可以跨左右和输出导航；行跳转在缺失侧、空文件和超长文件中不会越界或跳错侧。
- 每种忽略规则及其组合都有确定性 fixtures；改变规则不会改变任何原始文本或保存内容。
- “按规则等价”与“字节完全相同”在模型和 UI 中可区分。
- 随机生成的两侧文本中，hunk 范围不重叠、顺序稳定；接受全部左侧/右侧分别精确重建对应快照。
- 手工编辑与 hunk 接受共享 Undo/Redo；编辑穿过 hunk 边界时不会把动作应用到错误位置。
- 保存前目标变化、目标被删除、权限丢失、磁盘写入失败和取消均不会留下部分文件或覆盖外部修改。
- 关闭含未保存输出的会话必定提示；另存为不会改变原目标。
- 生成的 patch 对新增、删除、重命名标签、空文件、Unicode、CRLF 和缺少最终换行均有 fixtures，并能精确重建右侧文本。
- 开关语法高亮或自动换行不改变 diff 数量、hunk 范围或保存结果；换行后左右对应 row 仍对齐。
- 10 万行少量编辑场景的比较时间不超过 1.4 基线的 2 倍；搜索下一项和接受单个小 hunk 保持交互级响应。
- 所有新错误和控件均有英文、简体中文文案及可访问名称。

## 后续版本接口与范围

### 1.6 — Three-way Merge & Tool Protocols

- 输入 `base / ours / theirs`，分别计算 `base→ours` 与 `base→theirs`，按 base 范围合并。
- 分类为单侧修改、两侧相同修改、可自动合并和真实冲突；输出沿用 1.5 编辑器、安全保存和事务日志。
- 独立 `grapecompare` CLI 提供阻塞式 `diff`/`merge` 命令、稳定退出码和 `--wait`。
- 提供可复制的 `git difftool`/`git mergetool` 配置；mergetool 只有在用户保存合并结果后返回成功。

### 1.7 — Repository & Finder Integration

- 比较工作区、index、提交和分支；只读本地 Git 对象，不执行 fetch、checkout、reset 或自动提交。
- Finder Quick Action 只接受恰好两个项目；通过 App Group/安全书签把明确选择的 URL 交给主 App。
- 明确区分 App Store 与直接下载构建：任意路径 CLI、Git 子进程和扩展权限必须逐项验证，不能假定沙盒版本等价。

### 1.8 — Images & Structured Data

- `Comparator` 路由层按内容类型选择文本、图片或结构化数据 surface。
- 图片首版提供并排、叠加/滑杆、尺寸与像素差热图，不声称支持“合并”。
- 结构化数据首版限定 JSON 和 plist，提供树路径对齐、键顺序忽略和原始文本回退；CSV/表格作为后续独立范围。
- 非文本 comparator 复用会话、导航和导出外壳，但不复用 `DiffHunk` 或文本保存规则。

## Release decision

只有 Phase A–E 和全部 acceptance gates 完成时才发布 1.5.0。三方合并、Git 仓库浏览、Finder、图片或结构化数据即使已有实验实现，也不作为 1.5 GA 的阻塞项或宣传能力。
